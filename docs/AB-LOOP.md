# 双代理自动循环（A 写 / B 审）

> 给"不想逐章审稿"的场景。主会话只做规划与调度，正文由 A 写、B 挑错，脚本做硬门禁。

## 角色

| 角色 | 是谁 | 职责 | 不做什么 |
|---|---|---|---|
| 总控 | 主会话 | S0–S4 规划、生成 brief、调度 A/B、跑门禁、checkpoint、S7 交付 | 不亲自写正文 |
| **A 写手** | 子代理（`subagent`） | 按 brief + 细纲 + 硬约束写一批（默认 5 章） | 不改设定、不改大纲、不越窗细纲 |
| **B 审查** | 子代理（`subagent`） | 只出问题清单：原句 + 问题类型 + 最小改法 | 不整章重写、不改设定、不发明新情节 |
| 门禁 | `scripts/` | 字数、细纲覆盖、钩子、重复率、成品自检 | 不做文学判断 |

## 一轮的固定顺序

```
brief（总控）
  → A 写 5 章
  → gate_all.py ×5（硬门禁，脚本判定）
     ├─ 有章不过 → 直接回 A 修（不浪费 B）
     └─ 全过 → B 审 5 章（软质量）
  → B 输出 P0/P1
     ├─ P0 = 0 → checkpoint，进下一批
     └─ P0 > 0 → 交回 A 修（最多 2 轮），仍有 P0 → 记 追踪/遗留.md 并继续
```

**硬门禁在前、LLM 审查在后**：先用脚本挡掉水文/重复/漏点，再让 B 花注意力在"读起来对不对"上。反过来会让 B 给出一堆脚本本来就能查出的空话。

## A 的输入（每批一份）

```
1. context_brief.py 的本批输出（前文尾部、未回收伏笔、硬约束、卷级远景）
2. 本批细纲（大纲/细纲/第NNN–MMM章.md）
3. 项目参数（字数、基调正负清单、世界规则）
4. 上一批 B 的 P1 清单（只作风格参考，不强制）
```

## A 的输出

```
- 每章一个文件 正文/第NNN章-标题.md（3000 字 ±10%）
- 每章写完追加一行到 追踪/状态.md，新增/回收伏笔写 追踪/伏笔.md
- 不写 成品/，不改 设定/、大纲/
```

## B 的输出格式（强制，否则无法自动处理）

```
P0（必须改，逻辑/设定/负清单违规）
1. 第012章 | 原句：「……」 | 问题：主角徒手撕开丧尸（违反负清单"禁止割草"） | 改法：改为「……」或删掉该动作
P1（建议改，节奏/文风/信息密度）
2. 第013章 | 原句：「……」 | 问题：整段解释人物心理，缺少外部动作 | 改法：换成具体动作与物件
```

规则：**每条必须能定位到章 + 原句**；没有原句的意见一律丢弃；B 一次最多 10 条，按严重度排序。

## 停止条件

| 情况 | 处理 |
|---|---|
| 单章 2 轮修不过 | 记 `追踪/遗留.md`，标 P1，继续下一批（不死磕） |
| 同一类 P0 在 3 章重复出现 | 停下，把该规则补进 设定/世界观.md 或负清单，再继续 |
| B 连续两批 0 问题 | 提高 B 的严格度或换审稿维度（如只看对话） |

## 成本

24 章 × 5 章/批 = 5 批；每批 A+B 至少 2 次子代理调用，加修复约 3 次 → **约 15 次子代理调用**。
想更省：批量调到 8 章；想更严：每章单独过 B（调用数 ×5，慢但细）。

## 为什么不让 B 直接改稿

B 直接重写会引入它自己的设定理解偏差，且你再也分不清"哪句是 A 写的"。**B 只出问题，A 负责改**，责任边界清晰，出问题也能回溯。
