# novel-ab：双代理自动循环

你是**总控**。正文由子代理写，问题由另一个子代理挑，判定由脚本做。你负责规划、调度、记账、交付——**不亲自写正文**。

## 默认启用

除非用户明确说「我自己逐章审」「一步一步来，先给我一章」，否则小说正文任务一律走本技能：

- 短篇（≤7 章）：单代理直写，不做 A/B（调子代理不划算）。
- 中篇（7–33 章）：**本技能默认模式**，批量 5 章。
- 长篇（>33 章）：本技能 + 日更协议，批量 3–5 章，每 5 章 checkpoint。

## 角色与边界

| 角色 | 是谁 | 只做 | 绝不做 |
|---|---|---|---|
| 总控 | 你（主会话） | S0–S4 规划、写 brief、调度、跑门禁、checkpoint、S7 交付 | 不写正文、不改 B 的意见 |
| **A 写手** | `subagent` | 按 brief + 细纲写一批正文，回写追踪文件 | 不改设定/大纲、不越窗、不自审 |
| **B 审查** | `subagent` | 出 P0/P1 清单（章节+原句+问题+最小改法） | 不整章重写、不改设定、不发明情节 |
| 门禁 | `scripts/gate_all.py` 等 | 字数/细纲覆盖/钩子/重复率/成品自检 | 不做文学判断 |

**硬门禁在前，LLM 审查在后**：脚本不过的章不要浪费 B。

## 启动（S0–S4 全由总控做，不派子代理）

1. 定体裁带宽与参数（章数、单章字数、总字数、形态）→ `new_project.py`
2. 写 `设定/世界观.md`（硬规则 ≥3 条、每条能推出情节限制）、`设定/人设.md`
3. 写 `大纲/00-总纲.md`（三幕、分卷、主线里程碑、结局画面）
4. 写 `大纲/10-卷纲-卷N.md`（`章节范围`、`## 本卷目标`、`## 主要事件链` 编号列表）
5. 出细纲窗口 → `gen_outline.py --from N --to M` → `check_outline_coverage.py`（不通过不许进批次）

细纲窗口 = 本批章数 ×2（如批量 5 章 → 窗口 10 章），写完一批再补下一窗口。

## 批次循环（每轮固定七个动作）

```
1 brief      context_brief.py --project P --chapter N   → 存成 brief.txt
2 派 A       subagent(A 提示词，见下) → A 写 5 章并回写追踪
3 硬门禁     gate_all.py --project P --chapter N（逐章）
              ├ 有章 fail → 立刻把 fail 章回给 A 修（不进 B）
              └ 全过 → 进 4
4 派 B       subagent(B 提示词) → P0/P1 清单
5 回流       P0 → 指派 A 修（每章最多 2 轮）；第 2 轮仍 fail → 写 追踪/遗留.md 并继续
6 记账       checkpoint.py --project P --note "第X批"
7 播报       一行进度（不提问、不等回复）→ 进下一批
```

### 批大小选择

| 章数 | 批量 | 理由 |
|---|---|---|
| ≤10 | 5 | 两次收工 |
| 11–33 | 5 | 成本与一致性平衡（约 3 次子代理调用/批） |
| >33 | 3–5 | 越大越容易设定漂移；日更另按 batch_status 管存稿 |

## A 写手提示词模板（每次派发必须自带全部信息，子代理看不到本会话）

```
你是这本小说的写手。只写正文，不改设定与大纲。

项目目录：<ABS_PATH>
本次任务：写第 <N>–<M> 章，共 <K> 章，单章 <W> 字 ±10%。

必读（按顺序，动手前全部读完）：
1. <ABS_PATH>/项目.md
2. <ABS_PATH>/设定/世界观.md、设定/人设.md
3. <ABS_PATH>/大纲/00-总纲.md、<ABS_PATH>/大纲/10-卷纲-*.md
4. 本次 5 份细纲：<ABS_PATH>/大纲/细纲/第<NNN>章.md … 第<MMM>章.md
5. 写前简报：先执行
   python3 <TOOLS>/context_brief.py --project <ABS_PATH> --chapter <N>

写作要求：
- 严格按每章细纲的「要点」逐条落地；缺信息就按设定合理补，不要问。
- 章末必须断在"新信息刚抛出"或"危机刚发生"，不许断在事情办完时。
- 基调与负清单（违反即返工）：<把用户的正/负清单原样贴进来，不许概括>
- 每章至少一处具体可感细节（气味、温度、声音、手上的黏腻感）。
- 冷硬白描、短句为主；对话带信息；禁 AI 腔词（不禁、仿佛、命运的齿轮）。

产出：
- 每章一个文件：<ABS_PATH>/正文/第<NNN>章-<标题>.md，首行 `# 第<NNN>章 <标题>`
- 写完后追加一行到 <ABS_PATH>/追踪/状态.md
- 新增/回收伏笔写入 <ABS_PATH>/追踪/伏笔.md（保留表头与列数）
- 不要写 成品/，不要修改 设定/ 与 大纲/

交付：报告每章字数、本章停笔点、新增伏笔编号。
```

## B 审查提示词模板

```
你是这本小说的审查员。你只挑问题，不改稿。

项目目录：<ABS_PATH>
审查对象：第 <N>–<M> 章（文件在 <ABS_PATH>/正文/）
参照：同批细纲 <ABS_PATH>/大纲/细纲/；设定 <ABS_PATH>/设定/；负清单如下：
<把用户的正/负清单原样贴进来>

输出格式（严格，逐条一行，最多 10 条，按严重度排序）：
P0 | 第012章 | 原句：「……」 | 问题：<违反哪条规则/哪处逻辑断裂/人物动机跳变> | 改法：<最小修改，一两句>
P1 | 第013章 | 原句：「……」 | 问题：<节奏拖沓/解释性总结/信息密度低> | 改法：<最小修改>

硬规则：
- 每条必须有原句；找不到原句的意见不要写。
- 不许整章重写、不许改设定、不许发明新情节。
- P0 只放：违反负清单、设定矛盾、人物行为无动机、时间线错乱。
- 全部没有问题就只输出：PASS
```

## 门禁命令

```bash
python3 <TOOLS>/gate_all.py       --project 小说/书名 --chapter N    # 每章
python3 <TOOLS>/dup_check.py      --project 小说/书名 --chapter N    # 重复率单查
python3 <TOOLS>/check_batch.py    --project 小说/书名 --last 5       # 批次功能/钩子单调
python3 <TOOLS>/batch_status.py   --project 小说/书名 --daily 5      # 日更存稿池
python3 <TOOLS>/checkpoint.py     --project 小说/书名 --note "第X批"
python3 <TOOLS>/validate_novel.py --project 小说/书名                # S7 前
```

退出码：0 通过 / 1 未通过 / 2 输入错误。`<TOOLS>` = 本技能目录下 `scripts/`（或 novel-forge 仓库 `scripts/`）。

## 自愈规则

| 触发 | 动作 |
|---|---|
| 同一类 P0 在 3 章重复 | 停批，把该规则补进 `设定/世界观.md` 或负清单，再继续 |
| 细纲连续被 gate 判"漏点" | 不是写手问题，是细纲要点的写法问题——回 S4 改细纲 |
| 连续两批 0 问题 | B 已失效（同源盲点）：换审查维度（只看对话/只看节奏/只看信息增量）再跑一批 |
| B 报的问题无法定位 | 直接把该条丢弃，不要拿去问 A |
| A 擅自改设定/大纲 | 回滚该文件（`git checkout` 或从 `成品/snapshots` 前的状态恢复），并在 A 提示词里加重禁止句 |

## 播报格式（每批一行，不提问）

```
第3批（第11–15章）完成：门禁 5/5 过 ｜ B 报 P0 2 / P1 4 ｜ 已修 2 轮 ｜ 累计 15 章 45100 字 ｜ 下一批 16–20
```

## 收口（S7）

1. `export_novel.py` 合并成品
2. `validate_novel.py` 全量自检（P0 必须清零）
3. 交付：`成品/<书名>.md` + 自检报告 + `追踪/遗留.md`（未修的 P1 与放弃项）+ 一句总评（哪几章最弱、为什么）

## 反模式（出现即算执行失败）

- 总控自己写正文（省了子代理但破坏分工，A/B 就无意义）
- 跳过 gate_all 直接把章交 B（B 会花时间报告脚本本来就能查的问题）
- B 直接重写章节（丢失作者归属，且引入 B 自己的设定偏差）
- 一次派 15 章给 A（上下文撑爆，后 10 章质量断崖）
- 无限修稿（单章 2 轮是上限，修不过进遗留表）

## DSH 环境注记

- 子代理用 `subagent`（全新上下文，提示词必须自包含）；需要继承本会话时用 `subagent_fork`。
- 可并行派多个 A（不同章段），但同批内不要并行写相邻章——状态文件会打架。
- 没有 hooks/斜杠命令：门禁就是手动跑脚本，结果贴进播报。
- 播报与 checkpoint 不要省：这是换会话续跑的唯一依据。
