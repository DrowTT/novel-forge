# 长篇小说标准工作流 v1.1

> 本文件是长篇小说创作的**规范流程**，后续所有技能、脚本、门禁的开发和改造都对齐本文件。
> 三层标记：**[A]** 创作决策（不可自动化，必须由作者或模型当场判断）；**[B]** 记账核对（可脚本化）；**[C]** 记忆/纪律（靠落盘 + 注入 + 断点）。

---

## 0. 总览

```
S0 立项 ──► S1 设定 ──► S2 总纲 ──► S3 卷纲 ──► S4 章纲(滚动窗口) ──► S5 章节生产循环 ──► S6 卷末审稿 ──► S7 定稿交付
                              ▲                │                      │            │
                              └──── 修订 ◄──────┴──────────────────────┴────────────┘
                                 (设定冲突 / 节奏问题 / 注水 / 文风漂移)
```

两条铁律：

1. **滚动规划**：只对接下来 5–10 章出细纲，写完一个窗口再排下一个。绝不一次性排完 300 章细纲（必然作废）。
2. **状态先于文采**：任何与 `设定/`、`追踪/` 冲突的句子，改句子不改设定；确需改设定，先写影响面再动手。

## 1. 阶段定义

### S0 前置：先定体裁带宽（决定后面全部工作量）

| 体裁 | 字数（中文惯例） | 3000 字/章换算 | 适用 |
|---|---|---|---|
| 短篇 | 0.5–2 万 | 2–7 章 | 试笔、单点情绪 |
| **中篇** | **2–10 万**（文学期刊常 3–6 万；网文平台常把 10–30 万也叫中篇） | **7–33 章** | 试水、验证基调，一轮能跑完 |
| 长篇 | 10 万以上（网文 30 万+） | 33 章以上 | 连载、要养书 |

选错带宽的后果：按长篇写中篇的故事 → 全是水；按中篇写长篇的骨架 → 三卷变一章。**S0 必须先把字数与章数钉死，再动 S1。**

### S0 立项与定位 [A]

| 项 | 内容 |
|---|---|
| 输入 | 一个题材方向（可含参照物：「像《XX》的节奏」） |
| 动作 | 定题材/形态/目标字数/单章字数/目标平台；可选：扫榜对标、拆 1–2 本同类书取结构 |
| 产物 | `项目.md`（书名、题材、形态、目标字数、单章字数、进度） |
| 门禁 | 一句话能说清：**谁**在**什么处境**下要**什么**、被**什么**挡住、失败代价是**什么** |
| 工具 | `scripts/new_project.py`；oh-story `story-long-scan`（扫榜）、`story-long-analyze`（拆文） |

### S1 设定层 [A]

| 项 | 内容 |
|---|---|
| 动作 | 世界观硬规则 ≥5 条（能约束情节，不是形容词）；主角 + 3 配角（外在目标 / 内在缺口 / 能力与限制 / 说话习惯）；势力与场景库 |
| 产物 | `设定/世界观.md`、`设定/人设.md` |
| 门禁 | 每条硬规则都能推出至少一个情节限制；任意两个主要人物之间存在不可调和的利益冲突 |
| 工具 | `chinese-novelist/references/guides/character-building.md`、`outline-template.md` |

### S2 总纲 [A]

| 项 | 内容 |
|---|---|
| 动作 | 三幕结构、分卷表（卷名 / 章数 / 卷目标 / 卷末转折）、结局预设（终点画面 + 主角最终状态） |
| 产物 | `大纲/00-总纲.md` |
| 门禁 | 每卷有明确转折；结局画面已定；主线里程碑可数（一般 3–5 个） |
| 工具 | `references/guides/plot-structures.md`（三幕/英雄之旅/起承转合） |

### S3 卷纲 [A]

| 项 | 内容 |
|---|---|
| 动作 | 本卷事件链（按章粗排）、本卷新增设定与角色、本卷要埋/要收的伏笔 |
| 产物 | `大纲/10-卷纲-卷N.md` |
| 门禁 | 事件链上每一环都改变主角处境；卷末状态 ≠ 卷首状态 |
| 工具 | —— |

### S4 章纲（细纲，滚动窗口）[A + B]

| 项 | 内容 |
|---|---|
| 动作 | 为接下来 5–10 章各写一份细纲：本章目标 / 核心冲突 / 信息增量 / 出场人物 / 停笔钩子 / 目标字数 |
| 产物 | `大纲/细纲/第NNN章.md` |
| 门禁 | ①连续 3 章不缺事件；②每章都有信息增量（读者知道了上一章不知道的事）；③每章结尾有钩子；④细纲合计能覆盖卷纲事件链 |
| 工具 | 计划：`gen_outline.py`（批量骨架）+ `check_outline_coverage.py`（覆盖校验）｜**当前缺口** |

### S5 章节生产循环（核心引擎）[B + C]

每章固定五步，缺一不可：

| 步 | 动作 | 工具 | 门禁 |
|---|---|---|---|
| 1 简报 | 生成写前上下文：项目信息 / 前两章尾部 / 未回收伏笔（含**逾期**）/ 最近状态 / 硬约束 / 卷级远景 | `scripts/context_brief.py` | 简报缺失即停，不凭记忆写 |
| 2 写 | 按细纲写单章，目标字数 ±15% | 模型 | 章节文件 `正文/第NNN章-标题.md` |
| 3 回写 | 更新 `追踪/状态.md` 一行、`追踪/伏笔.md`（新增/回收）、必要时 `追踪/时间线.md` | 模型 + 脚本校验 | 三份追踪文件与本章事实一致 |
| 4 门禁 | 字数达标、细纲要点覆盖、与设定/前文无冲突、无大段重复 | `check_chapter_wordcount.mjs`、`check_chapter_plan.py`、`dup_check.py` | 任一不过 → 当场补写/重写，不留到下一章 |
| 5 记账 | 每 5 章 checkpoint：更新 `项目.md` 进度、追加 `CHANGELOG.md`、导出一份成品快照（**日更 5 章时，一个 checkpoint 正好等于一天**） | `export_novel.py` | checkpoint 缺失不允许继续批量写 |

**原则**：一次一章。不要连写多章再统一回写追踪——上下文一断就全错。

### S6 卷末审稿 [A + B]

| 项 | 内容 |
|---|---|
| 动作 | 多视角审查（编辑/读者/逻辑/节奏）、去 AI 味、节奏诊断；输出 P0/P1 清单并最小改动修复 |
| 产物 | `审稿/卷N-审稿.md` + 修订后的正文 |
| 门禁 | P0 全清；伏笔无悬空（逾期项要么回收要么明确放弃）；文风统计与本卷基准偏差在阈值内 |
| 工具 | `story-review`、`story-deslop`、`novel-longform/scripts/文风统计.py`、`原文重合检查.py` |

### S7 定稿交付 [B]

| 项 | 内容 |
|---|---|
| 动作 | 合并成品、全量自检、导出 |
| 产物 | `成品/<书名>.md`（标题页 + 目录带字数 + 正文）、自检报告 |
| 门禁 | 章号连续不跳；标题统一；每个文件有且仅有一个 H1；总字数达标；人物名/设定名全库一致；伏笔状态无「未回收」且无逾期 |
| 工具 | `scripts/export_novel.py`｜计划：`validate_novel.py`｜**当前缺口** |

## 2. 文件契约

```
小说/<书名>/
├── 项目.md              # 书名/题材/形态/目标字数/单章字数/进度/下一交付
├── 设定/
│   ├── 世界观.md         # 硬规则、势力、地理、日常细节
│   └── 人设.md           # 主角+配角：目标/缺口/限制/说话习惯
├── 大纲/
│   ├── 00-总纲.md        # 三幕 + 分卷表 + 结局预设
│   ├── 10-卷纲-卷N.md    # 事件链、新增设定、伏笔计划
│   └── 细纲/第NNN章.md   # 目标/冲突/信息增量/钩子/字数
├── 正文/第NNN章-标题.md   # 一章一文件
├── 追踪/
│   ├── 状态.md           # 章节|时间|地点|在场|关键物|未结事项
│   ├── 伏笔.md           # 编号|埋设章|内容|指向|计划回收章|状态
│   ├── 时间线.md         # 时间|事件|章节|影响
│   └── 发布.md           # 章号|状态(存稿/已排期/已发布)|发布日期|追读数据（连载必填）
├── 审稿/卷N-审稿.md
├── 成品/<书名>.md
└── CHANGELOG.md          # 每 5 章一条：写了什么、改了什么、遗留什么
```

兼容布局：`chinese-novelist` 原生布局（`00-人物档案.md` / `01-大纲.md` / `02-写作计划.json` / `03-文风基准.md` / `第NNN章-标题.md` 平铺）也承认，但**同一本书只用一种**。

## 3. 断点与续跑协议 [C]

| 触发 | 动作 |
|---|---|
| 每 5 章 | checkpoint：`项目.md` 进度 + `CHANGELOG.md` + 成品快照 |
| 每卷末 | S6 审稿；更新卷纲为「已发生」状态；重排下一个细纲窗口 |
| 会话中断/换模型 | 读 `项目.md` → 跑 `context_brief.py` → 从下一个未完成细纲继续，不重写已定稿章 |
| 设定被推翻 | 先写「影响面清单」（涉及哪些章、哪些伏笔），再改设定，再回改正文 |

---

## 4. 失败模式 → 对应门禁

| 失败模式 | 症状 | 门禁位置 |
|---|---|---|
| 水文 | 字数够但没推进 | S4 信息增量 + S5-4 细纲覆盖检查 |
| 自相矛盾 | 第 12 章和第 3 章设定冲突 | S5-1 简报注入硬约束 + S5-4 冲突检查 |
| 烂尾伏笔 | 埋了不收 | S5-1 逾期告警 + S6 P0 |
| 重复描写 | 景物/心理段落复用 | S5-4 重复检测（n-gram） |
| 文风漂移 | 越写越像 AI 总结 | S5 文风基准注入 + S6 文风统计 |
| 人物走形 | 说话方式前后不一 | S1 说话习惯 + S6 人物一致性检查 |
| 长程遗忘 | 忘了卷目标和主角弧线阶段 | S5-1 卷级远景区块 |
| 章号/文件混乱 | 跳号、重名、多 H1 | S7 自检 |

## 6. 与人协作的边界

| 由人（或模型代作者）决定 [A] | 由脚本强制 [B/C] |
|---|---|
| 题材取舍、主角设定、卷目标、每章细纲内容、结局画面 | 字数、覆盖度、重复率、伏笔到期、章号连续性、成品拼装、checkpoint |

**不要试图自动化左列**——自动化之后产物会变成模板文；右列不自动化，长篇必崩。

## 7. 连载模式（日更）

日更 5 章 = **12500 字/天**（按单章 2500）。这套流程的结构支持它，但必须叠加下面 6 条机制；否则写到第 3 天就会掉追读或断更。

### 7.1 批次语义：一天 = 一个 batch

```
批次开始 → 今日 5 章细纲确认 → 逐章 S5 循环 → 批次门禁 → checkpoint → 次日预告
```

- 批次开始先跑一次 `context_brief.py` 拿"昨天停在哪 + 逾期伏笔 + 卷级远景"，一次生成 5 章简报，不要每章重跑。
- 批次结束必须做 checkpoint，并把**次日第 1 章的钩子**写进 `项目.md` 的「下一交付」。
- 单次会话写不完 5 章是正常的：写 2–3 章就 checkpoint 落盘，下一会话续写，**不允许在内存里攒 5 章再落盘**。

### 7.2 存稿池（buffer）—— 日更的命门

| 存稿量 | 状态 | 动作 |
|---|---|---|
| ≥ 10 章（2 天） | 健康 | 正常节奏，可做改稿与优化 |
| 5–9 章 | 警戒 | 停止任何回改，优先产能 |
| 1–4 章 | 危险 | 只写不审，S6 审稿推迟到 buffer 回正 |
| 0 章 | 断更 | 应急：发回顾章/番外/缩章（1800 字），同时补 buffer |

存稿台账：`追踪/发布.md`（章节号 | 状态：存稿/已排期/已发布 | 发布日期 | 平台数据）

### 7.3 冻结机制：已发布章节不可回改

- 已发布章节正文 **只读**。发现问题只能在前向章节补救（callback/patch），不能改历史。
- 写前检查：`追踪/发布.md` 里状态为「已发布」的章，禁止进入改写流程。
- 需要大改（设定级冲突）时，走「设定修订 → 影响面清单 → 前向补救」，不改已发章。

### 7.4 追读门禁（连载专属，比字数重要）

| 指标 | 采样 | 触发动作 |
|---|---|---|
| 章末钩子强度 | 每章标注：悬念/危机/信息反转 | 连续 3 章同级 → 强制换型 |
| 章节功能分布 | 每 5 章统计：推进/爽点/铺垫/情感 | 连续 3 章同功能 → 下一章强制换型 |
| 追读率 / 完读率 | 每日记录到 `追踪/发布.md` | 连续 3 天下滑 → 每 10 章复盘，重排细纲窗口 |
| 断章位置 | 每章 | 必须断在"新信息刚抛出"或"危机刚发生"，不断在事情办完时 |

### 7.5 平台合规（发布前必过）

- 单章字数下限（番茄 2000+ / 起点 2000–3000，按 `项目.md` 的目标平台）；
- 章节名规范（不超长、不剧透结局、不用敏感词）；
- 敏感词与错别字校对（`story-proofread` 类流程）；
- 存在 `审稿/` 的 P0 未清项时不允许发布。

### 7.6 断更恢复

- 中断后先补 buffer，**不要**回头重写历史章节；
- 恢复第 1 天降为 3 章，第 2 天回 5 章；
- 补更期间跳过 S6 审稿，攒到 buffer ≥ 10 章后一次性补审。

### 7.7 日更与 S0–S7 的对应

| 阶段 | 一次性成书 | 日更连载 |
|---|---|---|
| S3 卷纲 | 全卷一次排完 | 只排当前卷 + 下一卷骨架 |
| S4 细纲 | 5–10 章窗口 | **窗口 = 2–3 天（10–15 章）**，每天批次内只确认当天 5 章 |
| S5 循环 | 连续写 | 按 batch 组织，一天一 checkpoint |
| S6 审稿 | 卷末一次 | 卷末 + buffer 健康时穿插，不在危险期审稿 |
| S7 交付 | 全书合并一次 | 每日快照 + 卷末正式导出 |
