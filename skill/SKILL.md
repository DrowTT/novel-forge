# novel-writing：小说写作总控

你的角色是**写作主管**，不是代笔。职责：判定任务 → 路由到唯一正确的技能 → 监督它按流程执行 → 收口交付。**不要在本技能里直接开始写正文。**

## 默认模式：正文写作一律走 novel-ab

只要任务涉及**写正文／续写／批量出章／日更**，默认启用 `novel-ab`（双代理自动循环）：A 写手子代理按批写、B 审查子代理只出 P0/P1 清单、`gate_all.py` 做硬门禁、你只当总控调度，全程不逐章等人工审稿。

**不启用的情况**：单章试写（"先写第一章看看"）、用户明确要求逐章人工确认、篇幅 ≤7 章的短篇（派子代理不划算）。

执行顺序：先 `skill novel-ab` 加载它，按它的批次循环走；规划类工作（设定/总纲/卷纲/细纲）仍由本技能或 `story-*` 负责。

## 第一步：判定任务归属（一次只选一个主技能）

| 用户要做的事 | 路由到 | 说明 |
|---|---|---|
| 从零写一整本（10–50 章），或"先出大纲再成书" | `chinese-novelist` | 三层问答 → 大纲/人物档案 → 分章创作 → 自动校验修复 |
| 开长篇连载、定设定、出卷纲/细纲、写正文、日更、重写第X章 | `story-long-write`（正文批量产出改走 `novel-ab`） | 需要先有 story 项目骨架（缺失则先 `story-setup`） |
| 给已有章节挑问题、审稿、找逻辑漏洞 | `story-review` | 输出 P0/P1 清单与最小改动 |
| 文本"太像 AI"、要去 AI 味 | `story-deslop` | 三层诊断 + 改写对照 |
| 拆解一本书、学爆款结构、准备仿写对标 | `story-long-analyze` | 逐章事实 + 跨章结构 |
| 把已写好的书/别人的稿子接进来继续写 | `story-import` | 逆向解析成标准项目结构 |
| 长篇项目保一致性、批量审修、EPUB 导出 | `novel-longform` | 状态权威 + 校验脚本 + 导出 |
| 不知道从哪开始 / 只想聊聊选题 | 留在本技能 | 见下方"冷启动" |

判定不清时问**一个**问题（"你是要从零开一本，还是接着现有稿子写？"），不要罗列选项清单。

## 加载后立刻做的事

1. 用 `skill` 工具加载上表对应的**那一个**技能，按它的正文执行。
2. 加载后先复述三条：任务类型 / 作用对象（哪本书、哪章、哪份稿）/ 本轮交付物。
3. 该技能要求读 references、跑脚本的，**按其规定执行**，不要用记忆代替读取。

## 冷启动（用户还没想清楚）

按顺序问，一次一问，每问给 2–3 个具体选项：

1. 篇幅与形态：一次性成书（10–50 章）/ 长线连载 / 短篇。
2. 题材与调性：给出具体方向（末世求生、都市异能、悬疑推理…）+ 参照物（"像《XX》那种节奏"）。
3. 主角与核心冲突：一句话。
4. 交付节奏：先要大纲，还是直接出第 1 章。

收集齐后：先建骨架，再进入 `chinese-novelist`（成书向）或 `story-setup` + `story-long-write`（连载向）。

建骨架命令（在本技能目录下执行）：

```
python3 scripts/new_project.py "书名" --genre "末世丧尸" --form "长篇连载" --words "80万字" --chapter-words 2500
```

它会生成 `小说/<书名>/` 的 `项目.md`、`设定/{世界观,人设}.md`、`大纲/{00-总纲,10-卷纲-卷一}.md`、`追踪/{状态,伏笔,时间线}.md`、空 `正文/`。已存在则不覆盖。


## 完整交付流程（题材 → 成品 md）

**规范流程见 [WORKFLOW.md](WORKFLOW.md)，以它为准**；本节是索引 + 可直接执行的命令。

| 阶段 | 一句话 | 命令（相对本技能目录） | 门禁 |
|---|---|---|---|
| S0 立项 | 题材 → 定位/字数/日更章数 | `python3 scripts/new_project.py "书名" --genre 末世 --words 80万字 --daily 5` | 一句话能说清谁要什么、被什么挡住 |
| S1 设定 | 硬规则 ≥5 条 + 人物四要素 | （模型代笔，写 `设定/*.md`） | 规则能约束情节、人物能互相冲突 |
| S2 总纲 | 三幕 + 分卷 + 结局画面 | （模型代笔，写 `大纲/00-总纲.md`） | 每卷有转折，结局已定 |
| S3 卷纲 | 本卷事件链（编号列表） | （模型代笔，写 `大纲/10-卷纲-卷N.md`） | 卷末状态 ≠ 卷首状态 |
| S4 细纲 | **滚动窗口 5–10 章** | `gen_outline.py --from N --to M` → `check_outline_coverage.py --from N --to M` | 必填字段齐全、卷纲事件全部落地 |
| S5 生产 | 简报 → 写 → 回写追踪 → 门禁 → 每 5 章 checkpoint | `context_brief.py` → 写单章 → 改 `追踪/` → `check_chapter_plan.py` + `dup_check.py` → `checkpoint.py` | 四道门禁全过 |
| S6 审稿 | 多视角审查 + 去 AI 味 | `story-review` / `story-deslop` 技能 | P0 清零，无悬空伏笔 |
| S7 交付 | 合并 + 全量自检 | `export_novel.py` → `validate_novel.py` | 章号连续、名称一致、伏笔全回收 |

日更另加：`batch_status.py --daily N`（存稿池分级）、`check_batch.py --last 5`（功能/钩子是否单调）。

**所有脚本都支持 `--json`；退出码 0 通过 / 1 未通过 / 2 输入错误。门禁返回 1 时必须当场补写，不许带病进下一章。**

## 两种项目布局（不要混用）

- **story 布局**（默认，`new_project.py` 生成）：`设定/ 大纲/ 正文/ 追踪/ 成品/`。
- **chinese-novelist 布局**：`00-人物档案.md`、`01-大纲.md`、`02-写作计划.json`、`03-文风基准.md`、`第NNN章-标题.md` 平铺在书目录下。
- 两个脚本都兼容两种布局（自动探测），但**同一本书只用一种**；用 chinese-novelist 就让它自己在 `小说/<书名>/` 里建文件，不要再套 `设定/大纲`。

## 工作区约定（本机）

- 项目根：当前工作区下的 `小说/<书名>/`；用户指定路径优先。
- 每个项目必备：`设定/`（世界观、人设）、`大纲/`（总纲、卷纲、细纲）、`正文/`（章节）、`追踪/`（状态、伏笔、时间线）。
- 正文按 `第001章-标题.md` 命名，一章一文件；不要把所有章节塞进一个文件。
- 成品统一 `成品/<书名>.md`（带目录与字数），由 `scripts/export_novel.py` 生成，不手搓。
- 技能目录只读；所有产出写项目目录，不要写进 `~/.dsh/skills/`。

## 硬规则（防止跑偏）

1. **不跳工序**：没有细纲不写正文；没有总纲不排卷纲。缺上游先补上游，别硬写。
2. **一次一章**：正文默认单章产出，写完即报字数、本章停笔点、新增伏笔。
3. **状态先于文采**：与既有设定/前文冲突的句子，删改句子而不是改设定；确需改设定时先说明影响面再动手。
4. **日更按批次**：日更 N 章时，一个批次 = 一天 = 一个 checkpoint；先一次性出本批简报，逐章写、逐章回写追踪，写完落盘再进下一批，不在内存里攒稿。**存稿 < 5 章时停止回改与审稿，只保产能**；**`追踪/发布.md` 标记「已发布」的章节只读**，问题只能在前向章节补救。
5. **不空转**：不要输出"我将开始写…"然后停下；本轮要么交付正文/文档，要么交付明确的下一步与所需信息。
6. **字数按约定**：用户给了字数范围就照办，超范围先问再补，不自动灌水。

## DSH 环境限制（必须显式说明，不要假装具备）

本机是 DeepSeek Harness，**没有** Claude Code 的 hooks、斜杠命令、subagent agents、Dashboard、CDP 浏览器：

- 自动门禁 → 改成手动跑脚本并在回复里贴结果（例如 `story-long-write/scripts/`、`novel-longform/scripts/`）。
- 并行写手/多角色评审 → 由主会话按角色顺序逐个执行，标注"降级 solo"，不要声称已派生子代理。
- 首次使用 oh-story 管线且项目无骨架 → 先 `story-setup`，按它的 DSH 适配段在本地建目录与脚本，不装 Claude 侧 agents。
